# 2026-11-26 Gameplay features (plan in six phases)

Request: the user chose six of the gameplay ideas (collection book and daily quests, time- and weather-driven fishing with hot spots, an hourly event, market prices that change by market and day, boat paint, a weekly board) and approved the plan. Branch `wt/gameplay`. Decisions: [0020](../decisions/0020-gameplay-clock-and-conditions.md) now; 0021 (progression), 0022 (market prices) and 0023 (paint) as those phases are built.

## Phases

| Phase | Content                                                                                     | Migration | State             |
| ----- | ------------------------------------------------------------------------------------------- | --------- | ----------------- |
| P0    | `game-clock.ts`, the sea follows the shared clock again, tests start at noon, decision 0020 | no        | built, not pushed |
| P1    | "Sổ" tab and the book, conditions of time and weather, hot spots, minimap rings             | no        | next              |
| P2    | Hourly event: ring, giant fish, local result                                                | no        |                   |
| P3    | Market price multiplier                                                                     | M1        |                   |
| P4    | Quests, weekly board, event tag and board, discovery result                                 | M2        |                   |
| P5    | Boat paint ([`2026-11-27-boat-paint.md`](2026-11-27-boat-paint.md))                         | M3        | in review         |

Every migration phase is built in this worktree and run on a throwaway PostgreSQL first; **nothing with a migration is pushed without the user's say** (a push to `main` applies it to the live database).

## P0 done

- `src/ocean/game-clock.ts` (slots, Vietnamese day and week, time left), `tests/game-clock.test.mjs`.
- The sea no longer starts pinned to noon: `sea-atmosphere.ts` has no initial pin, `babylon-scene.ts` steps the atmosphere with the shared server clock, `settings-weather.ts` says "Giờ thật". Browser tests start at noon through `VITE_TEST_NOON` (`scripts/lib/dev.mjs`, `scripts/test-browser.mjs`). `tests/atmosphere.test.mjs` pins all of it.

## P1 logic done (no user interface yet)

- `fishing.ts`: an optional `Conditions` for `rollFish` and `planRound`, neutral when absent (same fish, same draws; `tests/fishing.test.mjs` unchanged); the `Angler` takes an optional `conditionsAt(x, z)` read when the lure lands.
- `src/ocean/fishing-conditions.ts` (time of day and weather from the shared clock, bounded; `habitatOf`), `src/ocean/hot-spots.ts` (three spots every 15 minutes, 100 % of slots placed, 8 to 13 % per island, about 3 microseconds a slot), `src/ocean/collection.ts` (the book's view model and its words). Tests: `fishing-conditions`, `hot-spots`, `collection`.
- `fishing-ui.ts` and `ocean.ts`: `worldMs()` (`Date.now() + clockOffset`, the clock the scene uses) is passed to the fishing UI, so a cast now fishes in the shared sea's time, weather and hot spots.

## P1 interface done

- The Sổ tab (`book-ui.ts`) with real fish models, hot-spot rings on both maps, "✦ Mới!" and a toast for a new species. `tests/ocean-book-browser.mjs` (844×390 and 667×375). The quest and event pages in the concept images are not built yet (P4, P2).

## P2 built

- `world-event.ts`, `event-ring.ts`, giants through `Conditions`/`rollFish`/`Catch.giant`, the quota on the device, messages when the lure lands in the ring or a hot spot, the event mark on both maps, the "Sự kiện" page of the Sổ. Unit tests pass (679). The browser test is written but not run: a `qa-runner` is measuring how flaky `ocean-fishing` is at each commit and a second browser test would disturb its numbers.

## P3 built (migration M1, not applied)

- `supabase/migrations/20261127120000_market_prices.sql`: the Vietnamese calendar (`game_day`, `game_week`), `market_pct`, `price_at`, and `economy_state(p_market)` / `economy_sell(p_fish, p_market, p_day)` replacing the old signatures. Checked on a throwaway PostgreSQL with `tests/economy-postgres.sh` (the harness has new scenarios: golden table, state prices equal sale pay, unknown market 22023, yesterday honoured and older refused, old-style call, one function per name, privileges). Mutation checks (a wrong golden value, a wrong constant) fail the harness.
- `src/ocean/market-prices.ts`, `economy-api.ts`, `platform/economy.ts`, `market-ui.ts` ("Giá hôm nay" line), `tests/market-prices.test.mjs`, `tests/ocean-market-browser.mjs` (price shown is the price paid at Hải Đăng).

## P4 built (migration M2, not applied)

- `supabase/migrations/20261128120000_progression.sql`: quest catalogue and daily quests, weekly stats, event results; `on_catch` (isolated, returns `{}` on failure) called from the restated `record_catch(p_species, p_kg, p_event)`; RPCs `economy_quests`, `economy_quest_claim`, `economy_weekly_board`, `economy_event_board`. The harness (`tests/economy-postgres.sh`/`.sql`) has new scenarios: quest choice, progress filters, claim once, the 120-coin cap, week and event edges, quota of three, pruning, failure isolation, privileges, one function per name. Deliberate breakages of the quota and the cap fail it. Found while testing: variable names that shadowed column names made `on_catch` fail silently (it now logs a warning), which is exactly what the isolation hides, so the harness reads the results.
- Client: `quests.ts`, `event-board.ts`, `leaderboard.ts` (weekly reader), `economy-api.ts` (types, in-memory economy), `platform/economy.ts`, `book-ui.ts`, `rank-ui.ts`, `market-ui.ts` (the catch queue carries the event hour and reports results), `ocean.ts`. Tests: `tests/quests.test.mjs`, `tests/ocean-quests-browser.mjs` (844×390 and 667×375).
